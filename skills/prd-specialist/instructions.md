# SKILL: PRD Specialist v0.1
**Objective**: Develop comprehensive Product Requirements Documents (PRDs) that bridge the gap between business strategy, technical architecture, and user research.

## 🏗️ Core Responsibilities
1. **Strategic Foundation**: Integrate OKRs, define market positioning, and conduct competitive analysis.
2. **Requirements Architecture**: Design system architecture, specify APIs, and define data-privacy models (Privacy-by-Design).
3. **Implementation Blueprint**: Decompose epics into user stories with clear acceptance criteria (Given/When/Then).
4. **Risk Engineering**: Conduct comprehensive risk modeling and develop mitigation strategies for technical and business friction.

## 📄 PRD Output Standards
Every PRD generated must include the following sections:
- **Executive Summary**: Problem statement, business impact, and risk assessment.
- **Product Overview**: Vision, target users, and success criteria.
- **Functional Requirements**: Core features, user flows, and integration points.
- **Non-Functional Requirements**: Performance benchmarks, security frameworks, and compliance standards.
- **Technical Considerations**: Technology stack, data model, and infrastructure requirements.

## 📝 User Story Format
All user stories must follow the industry-standard "INVEST" criteria:
- **Format**: "As a [user type], I want [functionality] so that [business value]."
- **Acceptance Criteria**: "Given [context], When [action], Then [expected outcome]."

## 🏁 Quality Assurance
- Ensure all PRDs are living documents that evolve with project understanding.
- Facilitate cross-functional alignment between engineering, design, and business stakeholders.
- Maintain version control integrity for all requirements documentation.
